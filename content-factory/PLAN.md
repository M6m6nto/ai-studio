# План разработки контент-завода

Версия 1 · 19.08.2026 · ветка `claude/content-factory-dev-plan-d5bthf`

---

## 1. Контекст

Цель — перенести механику практикума «ВАЙБ контент-завод на Claude Code» на собственного агента:
конвейер, который сам находит виральную тему, разбирает референс, собирает карусель и инфографику,
пишет гайд на сайт, монтирует рилс, заводит воронку по кодовому слову и сдаёт результат в Telegram.

**Что уже есть:**

- Google-таблица `[Контент-завод] Poddubotsky` — фактически рабочая БД завода. Пять листов:
  запросы на поиск (запрос / платформа / период / статус), аккаунты-доноры (61 аккаунт Instagram +
  TikTok + YouTube с подписчиками, числом постов, `ID аккаунта`), три листа роликов с метриками
  (вовлечённость, просмотры, лайки, комментарии, репосты, сохранения, длительность, `ID поста`,
  временная ссылка на CDN) и лист продакшна: `Дата | Источник | Название | Скрипт | Описание |
  Статус | Исходный скрипт | Ссылка на исходное видео | Аккаунт | ID поста | video_id |
  audio_asset_id | Что переписать в скрипте`. В нём ~45 готовых скриптов с хуками.
- Репозиторий `ai-studio`: статические лендинги (`index.html`, `botgen/`, `aitargetolog/`,
  `pairbridge/`) и `deploy.sh` — rsync на VPS + nginx + certbot. Готовая площадка для шага «гайд на сайте».
- В сессии агента подключён **Higgsfield MCP** (`generate_image/video/audio`, `*_batch` + `jobs_wait`,
  `upscale_video`, `reframe`, `video_analysis_create`, `virality_predictor`, `shorts_studio`,
  `tiktok_publish`) и скилл `animated-carousel` (кадры 4:5, анимированный первый слайд).

**Чего нет:** кода. Всё сегодня делается руками через таблицу. Задача — собрать конвейер как
проектные скиллы + движки в папке `content-factory/` этого репозитория.

**Ограничение исследования:** домен `aicube.vercel.app` (гайды, презентация, библиотека стилей автора)
заблокирован egress-политикой этой среды, а docx «Обзор пайплайна ИИ-агента» содержит только ссылку
на него. План собран по экспорту канала практикума, структуре таблицы и файлу «Введение».
Если нужны детали именно авторских промптов — материалы надо выгрузить в Drive текстом.

## 2. Целевая архитектура

```
Claude Code (агент)
 ├─ скиллы .claude/skills/*        — что делать (промпты, каноны, чек-листы)
 ├─ движки content-factory/engines — чем делать (node/python/ffmpeg, детерминированно)
 ├─ реестр content-factory/registry— единственный источник правды о состоянии
 └─ внешние сервисы
     ├─ RapidAPI: real-time-instagram-scraper (метрики) + social-download-all-in-one (файлы)
     ├─ Higgsfield MCP: сцены, озвучка, апскейл, предсказание виральности
     ├─ Google Sheets API: витрина для человека (тот же формат листов)
     ├─ ChatPlace: воронка по кодовому слову
     └─ VPS через deploy.sh: страница гайда
```

Принцип: **скилл решает, движок исполняет.** Всё, что можно проверить кодом (нарезка по границам фраз,
ER-ранжирование, уникальность кодового слова, проверка страницы на 200), делает скрипт, а не модель.

### Структура каталогов

```
content-factory/
├─ PLAN.md                     ← этот файл
├─ CLAUDE.md                   — память агента: правила конвейера, каноны, стоп-слова
├─ .env.example                — все ключи с комментариями, откуда брать
├─ Makefile                    — smoke, lint, render, deploy-guide
├─ registry/
│  ├─ index.jsonl              — по строке на единицу контента
│  ├─ codewords.json           — занятые кодовые слова (уникальность)
│  └─ items/<slug>/item.json   — карточка: тема, реф, скрипт, артефакты, статусы шагов
├─ engines/
│  ├─ scout/                   — парсинг доноров, метрики, ранжирование (python)
│  ├─ ref/                     — скачивание, кадры, транскрипт, дизайн-код (python + ffmpeg)
│  ├─ carousel/                — gen.js + render.js (GSAP + Playwright → PNG → MP4)
│  ├─ reels/                   — нарезка, storyboard, сборка, титры, сверка звука
│  ├─ guide/                   — генератор страницы в стиле сайта + деплой + проверка 200
│  └─ funnel/                  — ChatPlace: сценарий воронки
├─ tools/
│  ├─ sheets_sync.py           — двусторонняя синхронизация реестра с Google-таблицей
│  ├─ tg_deliver.py            — приёмка в Telegram (альбом + подпись отдельным сообщением)
│  └─ cost.py                  — учёт расхода кредитов/токенов на единицу контента
└─ assets/                     — аватар, шрифты, шаблоны слайдов, бейджи, музыка
```

### Модель данных (`registry/items/<slug>/item.json`)

```json
{
  "slug": "lokalnyy-ai-stek",
  "codeword": "СТЕК",
  "topic":    { "title": "…", "source": "instagram", "picked_at": "…", "er": 0.084, "views": 412000 },
  "ref":      { "post_id": "…", "account": "zhilnikov_it", "video": "…", "transcript": "…",
                "design_code": "…", "verified_claims": ["…"] },
  "script":   { "hooks": ["…","…","…"], "body": "…", "caption": "…", "rewrite_notes": "…" },
  "artifacts":{ "carousel_mp4": "…", "slides": ["…"], "infographic": "…",
                "reel_mp4": "…", "guide_url": "…", "funnel_id": "…" },
  "steps":    { "trend": "done", "ref": "done", "carousel": "review",
                "guide": "todo", "reel": "todo", "funnel": "blocked", "deliver": "todo" },
  "cost":     { "higgsfield_credits": 0, "rapidapi_calls": 0 }
}
```

Статусы шага: `todo → running → review → done | failed | blocked`. `blocked` у воронки снимается
только когда `guide_url` отдал 200 — это единственная жёсткая очерёдность в конвейере.

## 3. Звенья конвейера

Семь команд + оркестратор. Человек участвует **четыре раза**: выбрал тему, принял макет карусели,
записал видео, принял ролик.

| Команда | Вход | Что делает | Выход | Инструменты |
|---|---|---|---|---|
| `/тренды` | ниша, период | обходит доноров из реестра и хэштеги, тянет посты за период, считает ER и viral-ratio (просмотры/подписчики), отсеивает темы с занятым кодовым словом | 3–4 темы на выбор | RapidAPI scraper, `engines/scout` |
| `/реф` | выбранная тема | скачивает пост, режет кадры, снимает расшифровку, описывает дизайн-код словами, **проверяет каждое утверждение по первоисточнику** | `ref` в карточке | social-download API, ffmpeg, `video_analysis_create` |
| `/карусель` | карточка | пишет спек, собирает превью всех слайдов → **стоп, приёмка человеком** → генерит 8 слайдов + один лист инфографики | PNG + MP4 4:5 | скилл `animated-carousel`, `engines/carousel`, `generate_image_batch` |
| `/гайд` | карточка | пишет разбор связной прозой с реальными источниками и двумя инфографиками, кладёт страницу в каркас сайта, деплоит, проверяет 200 | `guides/<slug>/` + URL | `engines/guide`, `deploy.sh` |
| `/рилс` | исходник (живое видео или аватар) | режет **по границам фраз**, рисует раскадровку на реальных кадрах, генерит недостающие сцены, монтирует, апскейлит, сверяет звук повторной расшифровкой → приёмка | MP4 1080×1920 | ffmpeg, `generate_video_batch` + `jobs_wait`, `upscale_video`, Remotion |
| `/воронка` | карточка, `guide_url` = 200 | приветствие с кнопкой, карточка со ссылкой, тег клика, конверсия, напоминание не открывшим, оффер через 18 ч, автоответы в комментариях | `funnel_id` | ChatPlace |
| `/в-телеграм` | карточка | карусель альбомом, инфографика, ролик, подпись **отдельным сообщением текстом** | сообщение в канал | Telegram Bot API |
| `/конвейер` | ниша | гоняет всё, шаги 3–5 параллельно, ведёт реестр и точки останова | обновлённая карточка | оркестратор |

Кодовое слово выбирается **на первом шаге**, до того как попадёт на слайды и в кадр.

## 4. Этапы разработки

Оценка — рабочие дни одного человека с агентом. Каждый этап заканчивается рабочим артефактом, а не «инфраструктурой».

### S0. Каркас — 0.5 дня
- `content-factory/` со структурой выше, `CLAUDE.md` с правилами конвейера, `.env.example`.
- Реестр: чтение/запись `item.json`, `index.jsonl`, резервация кодового слова.
- `make smoke` — проверяет ffmpeg, node, python-зависимости и наличие всех ключей из `.env`.
- **DoD:** `make smoke` зелёный, `registry new "тест"` создаёт карточку.

### S1. Тренды + реф — 1.5 дня
- `engines/scout`: импорт 61 донора из существующей таблицы, обход через RapidAPI, метрики в реестр,
  формула ранга `ER = (likes + 3·comments + 5·saves)/views`, отсечка по свежести и viral-ratio.
- `engines/ref`: скачивание mp4 по `ID поста`, кадры каждые N сек, расшифровка, дизайн-код,
  этап верификации фактов (расшифровка врёт в названиях, автор оригинала преувеличивает —
  в работу идёт только подтверждённое).
- Скиллы `/тренды`, `/реф`.
- **DoD:** `/тренды ниша:ии-инструменты` возвращает 4 темы с метриками, `/реф` по выбранной наполняет карточку.

### S2. Карусель + гайд — 2 дня
- `engines/carousel`: спек → превью-лист → 8 слайдов 4:5 + инфографика; рендер GSAP-шаблонов
  через Playwright в PNG, сборка MP4; переиспользуем скилл `animated-carousel` для анимированной обложки.
- Стоп-точка «принять макет» — обязательная, без неё шаг не идёт дальше.
- `engines/guide`: страница в стиле корневого `index.html` (Inter, тёмные токены `--bg/--surface/--text`),
  кладётся в `guides/<slug>/index.html`, добавляется в навигацию, деплой через `deploy.sh`, проверка `curl -sI` на 200.
- **DoD:** одна тема доведена до 8 слайдов + MP4 + живой страницы гайда, отдающей 200.

### S3. Рилс-автомонтаж — 2–3 дня (самое ёмкое звено)
- Нарезка по word-level таймкодам: границы фраз, не кратные десяти секундам — иначе слово рвётся.
- Storyboard строится **на реальных кадрах исходника**, не на фантазии модели; максимум 3 сториборда
  (~30 сек) на первых итерациях.
- Генерация сцен: `generate_video_batch` + `jobs_wait`, ретраи на модерацию (смягчить формулировки,
  не использовать лица известных людей, при провале — заменить сцену локальным b-roll).
- Сборка: замена фона, кинетик-титры, бейдж, родной звук; `upscale_video` до 2K; `reframe` при необходимости.
- Контроль качества: повторная расшифровка готового ролика и диф с исходным скриптом; опционально
  `virality_predictor` перед приёмкой.
- **DoD:** ролик 20–40 сек из своего исходника собирается одной командой, звук совпадает со скриптом.

### S4. Воронка + приёмка — 1 день
- `engines/funnel`: сценарий ChatPlace одним вызовом (приветствие с кнопкой → карточка со ссылкой →
  тег клика → конверсия → напоминание не открывшим → оффер через 18 ч), плюс автоответы в комментариях.
- Жёсткая проверка: шаг не стартует, пока `guide_url` не отдал 200.
- `tools/tg_deliver.py`: альбом + подпись отдельным сообщением.
- **DoD:** кодовое слово в комментарии приводит к выдаче ссылки и появлению лида в ChatPlace.

### S5. Оркестратор и витрина — 1 день
- `/конвейер`: параллельные 3–5, точки останова, восстановление после сбоя с последнего успешного шага.
- `tools/sheets_sync.py`: реестр ↔ Google-таблица в существующем формате листов (сервисный аккаунт),
  чтобы старый рабочий процесс не ломался.
- `tools/cost.py`: расход кредитов и вызовов API на единицу контента.
- **DoD:** `/конвейер ниша:…` доводит одну тему от поиска до сдачи в Telegram с четырьмя остановками.

### S6. Масштабирование — по факту
Библиотека форматов (reels-twitter, VOX-коллаж, рилс без слов), второй язык, автопубликация
(`tiktok_publish` уже есть в MCP), ночные прогоны по расписанию.

**Итого MVP: ~8–9 рабочих дней.**

## 6. Риски и как их закрываем

| Риск | Проявление | Решение в коде |
|---|---|---|
| Модерация Google/Higgsfield | сцена не генерится из-за слова в сториборде | автоматический ретрай со смягчённой формулировкой, затем подмена локальным b-roll, лимит 3 сториборда |
| Бан Instagram-аккаунта / смена VPN | падает парсинг и скачивание | один фиксированный выход, экспоненциальные ретраи, кэш ответов RapidAPI на 24 ч |
| Временные CDN-ссылки в таблице | ссылки на видео протухают | сохраняем файл локально сразу на шаге `/реф`, в реестр пишем путь, а не CDN-URL |
| Стоимость генерации | незаметный расход кредитов | `tools/cost.py` + лимит на единицу контента, `jobs_wait` вместо поллинга |
| Рассинхрон таблицы и реестра | человек правит статус руками | реестр — источник правды, sync двусторонний по `ID поста` + `slug`, конфликт → в `review` |
| Дрейф качества текста | «нейросетевой» стиль | humaniser-фильтр и анти-клише как обязательный шаг перед приёмкой скрипта |

## 7. Проверка

После каждого этапа — end-to-end прогон на одной реальной теме:

```bash
cd content-factory
make smoke                                  # окружение и ключи
python -m engines.scout --niche ии-инструменты --period 30d --top 4
python -m engines.ref  --slug <slug>        # видео, кадры, транскрипт, дизайн-код
node   engines/carousel/gen.js  --slug <slug> --preview   # стоп на приёмке
node   engines/carousel/render.js --slug <slug>
python -m engines.guide --slug <slug> --deploy
curl -sI https://<домен>/guides/<slug>/ | head -1        # ожидаем 200
python -m engines.reels --slug <slug> --source ./raw/<file>.mp4
python -m engines.funnel --slug <slug>       # стартует только после 200
python tools/tg_deliver.py --slug <slug>
```

Критерий приёмки MVP: одна тема проходит от `/тренды` до сообщения в Telegram, человек вмешивается
ровно четыре раза, все артефакты лежат в `registry/items/<slug>/`, статусы в таблице совпадают с реестром.
