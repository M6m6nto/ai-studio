# Контент-завод — память агента

Этот файл читает Claude Code при работе в `content-factory/`. Здесь — правила конвейера,
а не описание кода (код см. `PLAN.md` и docstring'и модулей).

## Принцип

Скилл решает, движок исполняет. Всё, что можно проверить кодом (ранжирование по ER,
уникальность кодового слова, границы фраз при нарезке, HTTP-статус страницы гайда) —
делает скрипт из `engines/`, а не рассуждение модели. Модель нужна там, где требуется
суждение: выбор темы из кандидатов, проверка утверждений по первоисточнику, приёмка макета.

## Реестр — источник правды

`registry/items/<slug>/item.json` — единственная карточка контент-единицы. Таблица
`[Контент-завод] Poddubotsky` — витрина для человека, синхронизируется с реестром
(`tools/sheets_sync.py`, появится в S5), но не заменяет его.

Статусы шага: `todo → running → review → done | failed | blocked`.
`review` значит «сделано автоматикой, ждёт подтверждения человека или агента» —
не пропускай его молча.

## Кодовое слово

Резервируется на первом шаге (`/тренды` → `Registry.reserve_codeword`), до того как
попадёт на слайды карусели и в кадр ролика. Никогда не бери тему, если её кодовое слово
уже занято — `rank.py` отсеивает такие кандидаты автоматически.

## Жёсткая очерёдность

Единственная обязательная последовательность во всём конвейере: **воронка стартует только
после того, как страница гайда отдала HTTP 200.** Всё остальное (карусель, гайд, рилс)
можно готовить параллельно.

## Точки остановки (человек участвует 4 раза)

1. Выбор темы из 3–4 кандидатов `/тренды`.
2. Приёмка макета карусели (превью 8 слайдов) до полного рендера.
3. Запись живого видео 20–40 сек по суфлёру для `/рилс`.
4. Приёмка готового ролика (сверка звука с расшифровкой).

Не проскакивай эти точки автоматически, даже если технически можешь сгенерировать дальше.

## Верификация фактов (`/реф`)

Расшифровка исходника может врать в деталях (названиях, цифрах), автор оригинала может
преувеличивать. В `item.ref.verified_claims` идёт только то, что подтверждено по
первоисточнику — это делает агент в диалоге, не автоматический скрипт.

## Higgsfield и /рилс — где кончается движок и начинается диалог

`engines/reel` не вызывает Higgsfield напрямую: у него нет REST-ключа, это
MCP-инструмент, доступный только внутри диалога агента. Разделение такое:

1. `/рилс --plan` — чистая механика: режет исходник по границам слов (не более
   3 сегментов, ~30 сек), берёт реальный кадр на каждый сегмент, пишет
   `storyboard.json` и кинетик-субтитры. Дальше стоп.
2. Агент в диалоге берёт `segment.reference_frame` из `storyboard.json` и сам
   решает, каким вызовом Higgsfield (`generate_video`, `motion_control` и т.д.)
   получить сцену с заменённым фоном — движок не диктует, какой именно
   MCP-инструмент использовать, это тоже суждение, не механика.
3. `/рилс --compose --scene N=путь` — агент подаёт обратно пути к готовым
   клипам. Сегменты без `--scene` идут локальным b-roll из исходника (не падаем
   и не ждём — см. ниже про модерацию).

Реальный AI-апскейл (`upscale_video`) — туда же: отдельный вызов агента поверх
уже собранного `reel_draft.mp4`, если разрешение требует поднять. В движке есть
только `upscale_placeholder` (ffmpeg lanczos) как черновая заглушка, не замена.

## ChatPlace и /воронка — та же логика, что с Higgsfield

`engines/funnel` тоже не ходит в ChatPlace напрямую: во вводных материалах
практикума сервис явно описан как «воронки из кодовых слов с MCP», то есть
это MCP-инструмент в диалоге агента, а не задокументированный REST с ключом
в `.env`. `/воронка --plan` строит `scenario.json` (триггер, приветствие,
напоминание, оффер, автоответчик) и жёстко проверяет `guide=="done"`
(подтверждённый 200) — дальше агент сам заводит воронку по этому сценарию
через MCP и подтверждает результат: `/воронка --set-funnel-id <id>`.

Egress в этой sandbox-среде блокирует `chatplace.io` (как и `aicube.vercel.app`)
на уровне сетевого прокси контейнера — ни `WebFetch`, ни Playwright-браузер
внутри этой сессии его не откроют. Если нужна точная интеграция с реальным
API ChatPlace — либо документация вставляется в диалог текстом, либо это
доделывается в среде, где MCP-инструмент ChatPlace физически доступен.

## Модерация генерации видео

При отказе генератора видео (Google Flow и подобные) на сториборде:
1. Смягчить формулировки в сториборде.
2. Не использовать лица известных людей (сетка на лицо помогает не всегда).
3. Убрать/наложить звук отдельно, если модерация цепляется за реплику.
4. Максимум 3 сториборда (~30 сек) — не растягивать эксперименты.
Если ничего не проходит — заменить сцену локальным b-roll, не терять время на переборе.

## Стиль текста

Скрипты и гайды проходят через фильтр «анти-нейросеть» (см. скилл `humaniser` из набора
практикума) перед приёмкой — без канцелярита и типичных ИИ-клише.
